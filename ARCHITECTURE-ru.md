## Архитектура

### Структура расширения

Расширение следует архитектуре WXT на основе entrypoints. Основные каталоги:

- **entrypoints/background/**: фоновый service worker — жизненный цикл расширения, события вкладок, бейдж и инициализация popup
- **entrypoints/popup/**: интерфейс popup (по щелчку на значке)
- **entrypoints/options/**: главная панель со страницами Список, Настройки, Импорт/экспорт, Синхронизация и Корзина
- **entrypoints/content/**: content scripts для контекстного меню на веб-страницах
- **entrypoints/common/**: общие утилиты, хранилище, хуки и константы
- **entrypoints/nice-newtab/**: собственная новая вкладка; фон перенаправляет URL новых вкладок согласно настройкам
- **entrypoints/types/**: типы TypeScript всего расширения

### Управление данными

Используется обёртка WXT над хранилищем браузера и утилиты в `entrypoints/common/storage/`:

- **tabListUtils**: список вкладок (категории, группы, вкладки)
- **settingsUtils**: настройки пользователя
- **syncUtils**: синхронизация GitHub/Gitee Gists
- **syncWebDAVUtils**: синхронизация WebDAV
- **recycleBinUtils**: удалённые элементы для восстановления
- **themeUtils**: тема и цвета
- **stateUtils**: состояние приложения
- **snapshotUtils**: версионируемые снимки и миграция
- **newTabUtils**: чтение сохранённого списка для новой вкладки

`storage/index.ts` создаёт экземпляры утилит и экспортирует слушатели. `instanceStore.ts` обеспечивает доступ внутри одного JS-контекста; память экземпляров не разделяется между фоном, popup и страницами.

### Основные модели данных

Типы заданы в `entrypoints/types/tabList.ts`:

- **TagItem**: категория с groupList
- **GroupItem**: группа вкладок с tabList
- **TabItem**: вкладка с URL, заголовком и favicon

Иерархия: TagItem (категория) → GroupItem (группа вкладок) → TabItem (вкладка)

### Интернационализация

Используется `react-intl`:
- Языки: упрощённый китайский (zh-CN), традиционный китайский (zh-TW), английский (en-US) и русский (ru-RU)
- Модули локалей в `entrypoints/common/locale/modules/`
- Локаль Ant Design через `antdMap`

### UI

- **React 18** и TypeScript
- **Ant Design 5** для компонентов
- **styled-components** для стилей
- **react-router-dom** для навигации страницы настроек
- **pragmatic-drag-and-drop** (Atlassian) для перетаскивания
- **react-virtuoso** для виртуальных списков (производительность)

### Разрешения расширения

Основные разрешения в `wxt.config.ts`:
- `storage`: сохранение данных
- `tabs`: управление вкладками
- `contextMenus`: контекстное меню
- `tabGroups`: нативные группы вкладок браузера
- `commands`: сочетания клавиш (только Chrome)
- `alarms`: расписание автосинхронизации
- `scripting`: внедрение content scripts

У Firefox часть разрешений условная из-за различий API.

## Ключевые файлы и паттерны

### Фоновый worker (`entrypoints/background/index.ts`)

- Инициализирует контекстные меню, команды клавиатуры и слушатели вкладок
- Ставит бейдж с числом открытых вкладок
- Настраивает заголовки страниц
- Инициализирует popup в зависимости от настроек

### Общие утилиты

- **contextMenus.ts**: регистрация и обработчики контекстного меню
- **commands.ts**: обработчики сочетаний клавиш
- **tabs.ts**: операции с вкладками (создание, закрытие, гибернация и т.д.)
- **keyMap.ts**: карта сочетаний клавиш
- **constants.ts**: константы и перечисления свойств настроек

### Структура страницы настроек

Каталог `entrypoints/options/`:
- **home/**: список вкладок с деревом навигации
- **settings/**: формы предпочтений
- **importExport/**: импорт и экспорт
- **sync/**: удалённая синхронизация (Gists/WebDAV)
- **recycleBin/**: восстановление удалённых элементов
- **snapshots/**: история ручных снимков и последний автоматический снимок

### Важные хуки

- **global.ts**: глобальная шина событий и сообщения
- **selectionBox.ts**: рамка множественного выбора
- **themeColors.ts**: цвета темы
- **treeData.ts**: операции дерева категорий и групп

## Правила разработки

### Обязательный export

Скриптовые точки входа WXT требуют соответствующего определения с default export. Для обычных общих модулей и скриптов из HTML такого общего требования нет. Примеры и соглашения приведены в [CONTRIBUTING](CONTRIBUTING-ru.md).

### Алиас путей импорта

Алиас `~` указывает на корень проекта и используется для межмодульных импортов:
```ts
import { something } from '~/entrypoints/common/utils';
```

### Стили

- styled-components для стилей компонентов
- тема Ant Design для единообразия UI
- цвета темы через themeUtils
- поддерживаются светлый и тёмный режимы

### API браузера

Используйте `browser.*` (кроссбраузерная обёртка WXT), а не `chrome.*`:
```ts
browser.tabs.query({}) // вместо chrome.tabs.query({})
```

### Хранилище

Вызывайте готовые утилиты, а не Storage API напрямую:
```ts
// Правильно
const settings = await settingsUtils.getSettings();

// Избегать
const settings = await storage.getItem('settings');
```

### Типы

Перед коммитом запускайте `pnpm run compile`.

### Сообщения коммитов

Сохраняйте процесс Fork → ветка от `origin/dev` → push в свой fork → PR в `dev` основного репозитория, описанный в [CONTRIBUTING](CONTRIBUTING-ru.md). В заголовке коммита используется английский тип и описание на китайском. Основные типы:
- `feat:` новая возможность
- `fix:` исправление ошибки
- `docs:` документация
- `refactor:` рефакторинг
- `style:` форматирование
- `test:` тесты
- `chore:` обслуживание

## Особенности браузеров

### Отличия Firefox

Во Firefox ограничены привилегированные URL:
- нельзя открыть URL `chrome:`, `javascript:`, `data:`, `file:`
- нельзя открыть привилегированные `about:` (например `about:config`)
- разрешение `tabGroups` необязательное (нужно согласие пользователя)
- разрешений `commands` и `favicon` нет

`isFirefox` в `wxt.config.ts` управляет сборкой. Runtime-модули используют `import.meta.env.FIREFOX` и проверки из `entrypoints/common/utils/support.ts`; группы Firefox также требуют необязательного разрешения.

### Политика безопасности контента

В `wxt.config.ts` разные CSP для Firefox и Chrome из-за более строгих требований Firefox.

## Тесты и качество

В проекте есть тесты Vitest с интеграцией WXT через `WxtVitest()`. Проверки включают:
- проверка типов TypeScript (`pnpm run compile`)
- ESLint без изменений (`pnpm lint:no-fix`); `pnpm lint` применяет исправления
- существующие тесты Vitest (`pnpm test` или отдельный файл)
- ручное тестирование в браузерах

## Удалённая синхронизация

Поддерживаются несколько бэкендов:
- **GitHub Gists**: личный токен с разрешением на работу с Gists
- **Gitee Gists**: альтернатива, если GitHub недоступен
- **WebDAV**: несколько учёток WebDAV

Стратегия: объединение (удаления по умолчанию не синхронизируются). Чтобы синхронизировать удаления, нужно вручную перезаписать удалённые данные.

## Производительность

- **react-virtuoso** для виртуальной прокрутки больших списков
- **lodash-es** (ES-модули для лучшей сборки)
- debounce обработчиков, чтобы не вызывать API слишком часто
- слушатели хранилища уведомляют подписчиков; каждый подписчик определяет нужное обновление

## Манифест расширения

WXT генерирует manifest.json из `wxt.config.ts`. Важное:
- локаль по умолчанию: `zh_CN`
- сочетания клавиш в секции `commands`
- homepage URL ведёт на GitHub
- отдельные настройки для Firefox gecko


## Модель данных и инварианты

`entrypoints/types/tabList.ts` определяет иерархию сохранённых данных:

```text
TagItem (категория, tagId)
└── groupList: GroupItem[] (сохранённая группа, groupId)
    └── tabList: TabItem[] (сохранённая вкладка, tabId)
```

Строковые ID сохранённых данных отличаются от ID вкладок/групп браузера. Нативные группы относятся к открытым вкладкам; группы NiceTab существуют независимо от них.

- Промежуточная область — особая категория (`static`, обычно `tagId: '0'`). `getTagList()` обеспечивает её наличие в начале списка.
- Закреплённые звёздочкой группы предшествуют остальным внутри категории. Вставка и перемещение могут менять `isStarred` в зависимости от позиции назначения.
- Блокировки категорий и групп влияют на удаление и изменение порядка. Проверяйте ограничения UI и методы хранилища; блокировка не означает универсальный запрет любых изменений.
- Копирование, перемещение, объединение и восстановление имеют разные правила ID, удаления дублей и удаления исходных данных. Сохраняйте различия, включая частичный отказ.
- Корзина сохраняет иерархию. `RecycleBinUtils` наследует `TabListUtils`, поэтому изменение базового поведения может затронуть оба хранилища.

Перед изменением операций прочитайте `.claude/skills/nicetab-dev/references/checklist.md`.

## Хранение и состояние

`entrypoints/common/storage/index.ts` создаёт экземпляры утилит и экспортирует `init*StorageListener`. `entrypoints/common/storage/instanceStore.ts` обеспечивает доступ между классами внутри одного контекста. Данные сохраняются через обёртку WXT; текущие доменные хранилища используют пространство `local:`, а не автоматическую облачную синхронизацию браузера.

| Владелец                           | Данные                                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------------------------- |
| `tabListUtils` / `newTabUtils`     | Иерархия в `local:tabList`; новая вкладка читает тот же список                            |
| `settingsUtils`                    | Настройки и значения по умолчанию в `local:settings`                                      |
| `themeUtils` / `stateUtils`        | Тема в `local:theme`; состояние UI/глобальное состояние в `local:state`                   |
| `recycleUtils` (`RecycleBinUtils`) | Удалённая иерархия в `local:recycleBin` и состояние очистки                               |
| `snapshotUtils`                    | Версионируемое `local:snapshots`; буфер автоснимков также использует глобальное состояние |
| `syncUtils`                        | Настройки Gist, история результатов и статус                                              |
| `syncWebDAVUtils`                  | Настройки WebDAV; историческое имя ключа — `local:syncWevDAVConfig`                       |

Не исправляйте написание постоянных ключей без миграции. Утилиты могут кешировать данные; запись или вызов `storage.watch` не обновляет автоматически каждое дерево React. Отдельно `entrypoints/common/utils/faviconDb.ts` ведёт IndexedDB-кеш иконок и неудачных загрузок.

## Основные процессы

### Отправка вкладок браузера в NiceTab

1. Действия popup, контекстных меню или команд поступают в `entrypoints/common/contextMenus.ts` и фоновый обработчик.
2. Если включён выбор назначения, `SendTargetActionHolder` показывает диалог; подтверждение продолжает отправку.
3. `entrypoints/common/tabs.ts` и `entrypoints/common/storage/tabListUtils.ts` выбирают и фильтруют вкладки, сохраняют поддерживаемые нативные группы и записывают иерархию.
4. Настройки определяют закрытие отправленных вкладок, открытие панели и уведомления. Существующие сообщения и пути обновления актуализируют интерфейсы.

### Изменение и восстановление сохранённых элементов

Меню Home, операции дерева, drag-and-drop и массовые действия сходятся в `entrypoints/options/home/hooks/treeData.ts` и утилитах хранилища. Локальный `refreshTreeData()` использует текущий список утилиты, а `init()` читает сохранённые данные. Другому контексту нужен путь повторного чтения/обновления, а не только локальная перерисовка.

Открытие вкладок/групп использует `tabs.ts` для выбора окна, обработки URL, группировки и выгрузки вкладок из памяти. Удаление после открытия зависит от настроек, успешности и блокировок.

### Импорт, экспорт и удалённая синхронизация

`entrypoints/common/utils/importExport.ts` разбирает и формирует внешние данные; `tabListUtils.importTags()` применяет добавление, объединение или перезапись. UI находится в `entrypoints/options/importExport`.

`entrypoints/common/storage/syncUtils.ts` обслуживает GitHub/Gitee Gists, `entrypoints/common/storage/syncWebDAVUtils.ts` — WebDAV. Оба поддерживают ручные/автоматические pull и push с объединением или принудительной перезаписью. Объединение сохраняет содержимое и не распространяет удаления; force заменяет данные назначения. Включение настроек зависит от конфигурации. Резервное копирование удалённых данных и обработка ошибок определяются конкретной реализацией и не означают общей транзакционной гарантии.

`entrypoints/common/alarms/autoSyncAlarm.ts` планирует автоматическую синхронизацию. Токены и адреса серверов относятся к пользовательским настройкам, а не к общим значениям репозитория.

### Снимки и восстановление при запуске

`entrypoints/common/storage/snapshotUtils.ts` управляет версиями снимков, ручной историей, миграцией старых данных и переносом автоматического буфера в сохранённый снимок. `entrypoints/background/handler.ts` отслеживает события вкладок/групп с debounce. Текущая автозапись основана на событиях; фон очищает старый alarm автосохранения.

При запуске фон отключает `snapshotStatus`, переносит предыдущий автоматический буфер, при необходимости восстанавливает его и включает запись в `finally`. Это защищает источник восстановления от немедленной перезаписи событиями самого восстановления. Снимки представляют открытые окна/вкладки браузера, а не просто дерево сохранённых категорий.

## Сообщения и отрисовка

```text
Компонент / событие браузера
    → доменная утилита → постоянное хранилище
    → локальное обновление, подписка на storage или runtime-сообщение
    → получатель читает данные / выполняет действие → обновление UI
```

- React Context и mitt работают в пределах одного JS-контекста. Общий mitt находится в `entrypoints/common/hooks/global.ts`, отдельный для Home — в `entrypoints/options/home/hooks/homeCustomEvent.ts`.
- `storage.watch` уведомляет только зарегистрированных слушателей.
- `entrypoints/common/utils/runtimeMsg.ts` передаёт типизированные сообщения между контекстами; протокол задан в `entrypoints/types/runtimeMsg.ts`. Утилита всегда отправляет сообщение фону и не собирает подтверждения обработки.
- `sendTabMessage` из `tabs.ts` адресует content scripts выбранных вкладок. На защищённых страницах получателя может не быть.
- `entrypoints/common/components/Root.tsx` предоставляет тему, локализацию и контекст, обрабатывает UI-сообщения. Сообщения обновления панели используют существующий механизм изменения URL/обновления.

Отправители, получатели и очистка подписок подробнее описаны в `.claude/skills/nicetab-dev/references/messages.md`.
